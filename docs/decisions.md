# Design decisions (agreed 2026-11-12)

Source: the Q1–Q17 Q&A session with the maintainer, plus the final design in Claude Design (`design/claude-design/FR265 Watch Face.dc.html`). When this document and the design disagree, follow **this document** for MVP scope and **the design** for pixel measurements.

## Background
- Previous faces: SHN EDO → Segment34 MkIII (dropped: ugly and laggy) → Focus Digital. On 2026-11-10 Focus Digital became paid ($2.75), so the maintainer decided to build a face of their own.
- The face is built for everyday health at a glance (Body Battery, stress, steps, intensity minutes), not for training.
- Inspired by Focus Digital (solid color blocks, big digits) and Dash PRO by Crafted.by.Mies (round gauges with rings, rounded pills). Both are closed source, so no code or assets are copied. Fonts come from Google Fonts (OFL).

## Implementation decisions (agreed 2026-11-12, second session)
Vocabulary follows `GLOSSARY.md`. These rows extend Q1–Q17; where one changes the design, the row says so.

| # | Topic | Decision |
|---|---|---|
| Q18 | Build order | Start with a tracer bullet (background, time band, time in a system font) that goes the whole way: build → sign → simulator → sideload to the watch. Then add elements one by one |
| Q19 | Process | Specs and tickets are GitHub issues on `fugo101/wellface` (changed 2026-11-26; was a short spec plus one ticket per step as markdown files under `.scratch/`). The spec of the face as built is `docs/spec.md`, which replaces the four specs that were kept there. Triage labels: `docs/agents/triage-labels.md` |
| Q20 | Git | The default branch is `main`. Every change goes through a pull request with a Conventional Commits title, squash-merged only; a repository ruleset requires the `Conventional PR title` and `Lint` checks (changed 2026-11-26; was commit straight to `master` with no feature branches, which had itself replaced one `feat/<slug>` branch per ticket on 2026-11-12). The maintainer approves every merge |
| Q21 | Date language | Weekday name follows the watch language, upper-cased with diacritics stripped. If a character is still missing from the font (Cyrillic, CJK…), fall back to English. Vietnamese weekdays use their short form: "Thứ 2"…"Thứ 7" → `T2`…`T7`, Sunday → `CN` (2026-11-13). The watch is currently set to English |
| Q22 | Time format | Always 24 h with a leading zero (`08:42`), whatever the watch's 12/24 h setting |
| Q23 | Date pill width | At least 96 px, grows to fit longer weekday names, stays centered, never wider than 272 px (the design's maximum; the time band is 288 px since 2026-11-14) |
| Q24 | Bottom field, goal not reached | If the step text doesn't fit, the step number shrinks from 22 to 18. If it still doesn't fit, the foot icon is hidden |
| Q25 | Bottom field, goal reached | `/ goal` is dropped: foot icon + step number, centered as a group, on the accent with black text. **Changes design frame 7** (`3.512 / 3.110` → `3.512`) |
| Q26 | Missing data | Body Battery: `--` in gray, track only. No step goal (missing or 0): bezel ring empty and no `/ goal`. No battery reading: all 10 segments off |
| Q27 | Intensity minutes | **Not** in the MVP |
| Q28 | AOD burn-in shift | Time + date cycle through offsets of at most ±4 px, one step per minute. Verified with the heat map |
| Q29 | Fields and metrics | Fields are named by position: left, center, right, bottom field and bezel ring. A field is only a place, size and well; the **metric** decides how it is drawn (gauge, zone segments, progress). The bezel ring only takes a goal metric. The MVP maps metrics to fields statically: stress → left, Body Battery → center, heart rate → right, steps → bottom field and bezel ring |
| Q30 | Test seam | `FaceModel` stays the only test seam. Besides colors, strings, angles and segment counts it also computes the text layout of the date pill and the bottom field (from the font catalog, the glyph widths, base and cap height generated with each font), the AOD burn-in offset, which long-press target a touch point hits, and, from the face config: its resolution (theme by name, Q40 fallback), the read plan, which frame parts each change kind invalidates, and the update that recomputes only those parts. Sensor reading, drawing and the font generator are checked by eye in the simulator |
| Q31 | Up-to-date stack | Everything used is current, nothing outdated: the latest Connect IQ SDK, the newest API level the FR265 supports (5.2, its firmware ceiling) as `minApiLevel`, no deprecated APIs (checked against the SDK docs), strict type checking, the latest stable versions of every tool and library, and fonts freshly downloaded from Google Fonts. Re-check versions at the start of each piece of work |
| Q32 | Font glyph sets | Each font contains only the glyphs it draws (see "Fonts to export"). `%` and `h` are dropped until a Q15 metric needs them |
| Q33 | Date too long | If the weekday name does not fit even in a date pill at its maximum width (272 px), the English abbreviation is used |
| Q34 | Bottom field last resort | If the step text still does not fit after shrinking the number and hiding the icon (only possible from 100.000 steps), `/ goal` is dropped |
| Q35 | AMOLED rule | Acceptance criterion for AOD: **less than 10% of screen luminance**, measured with the simulator heat map (the SDK rule since the Venu 2). The hard "no pixel lit > 3 minutes" requirement is dropped. The ±4 px burn-in shift (Q28) stays, as Garmin recommends, to limit physical burn-in |
| Q36 | Heart-rate refresh | While the screen is awake (high-power mode), heart rate alone is re-read every second, and only while a field shows it; the field showing heart rate updates when it changes. All other data stays once a minute and on wake. AOD shows no heart rate, so nothing is read there |
| Q37 | Heart-rate zone colors (agreed 2026-11-13) | Each lit zone segment takes its own zone's color, in Garmin's order: zone 1 gray `#B4B4B4`, 2 blue `#4DA6FF`, 3 green `#4CD964`, 4 orange `#FF8A3D`, 5 red `#FF4D4D`. Garmin's manuals name the colors but publish no values; these were chosen for the dark background, and zones 4 and 5 reuse the warning colors on purpose. The colors are a theme role. Replaces the accent for lit zone segments (Q3 otherwise unchanged) |
| Q38 | Date format (agreed 2026-11-14) | The date pill shows the weekday, a space, then day/month as `dd/mm`, always two digits each (`THU 12/11`, `T2 03/11`), in every language and whatever the watch's date-format setting. The English fallback (Q21, Q33) uses the same format. Replaces the day-of-month-only date of the MVP (`T5 12`, no leading zero); Q21's weekday rules are unchanged |
| Q39 | Well rims (agreed 2026-11-14) | A 2 px well rim, lighter than the background: accent × 0.48 (mint → `#446D58`; changed 2026-11-14, was the fixed `#4D5852`), around the wells of the time band, the left, center and right fields and the bottom field, so the wells keep their shape when the watch dims the screen. The battery bar and the date pill have none. Long-press targets stay the wells (R + 6), rims not included (the bottom field's target is padded, Q45) |
| Q40 | Field kinds (agreed 2026-11-14) | Each field kind accepts only the drawing styles it can draw: a round field (left, center, right) takes a metric drawn as a gauge or as zone segments; the bottom field and the bezel ring take a goal metric. A field asked to show any other metric shows its default metric instead (today's mapping, Q29). The same metric may appear in several fields, as steps does on the bottom field and the bezel ring. Making other pairs drawable (steps in a round field, a non-goal metric in the bottom field or on the bezel ring) is not planned |
| Q41 | Seconds (agreed 2026-11-14) | Two-digit seconds (`07`) while the screen is awake (high-power mode) only, hidden in low power and AOD, where nothing about seconds is read or drawn. Also hidden, not left frozen, once the face stops getting per-second updates (`onEnterSleep`, about 10 s after a wake) while a tap keeps the screen lit in high power (amended 2026-11-15). Manrope ExtraBold 26 (the existing 26 px number font, no new file), ink color on the time band, left-aligned at x 309 (6 px after the minutes), baseline y 155 like the time. Hours:minutes never move. A change of the second alone redraws only the seconds and recomputes nothing else; the cost limits are in Q44. Replaces "no seconds" (Q2) |
| Q42 | Themes (agreed 2026-11-14) | 10 themes, each a single accent C: Mint `#8EE3B8` (default), Volt `#D4F26A`, Sage `#B4CDA0`, Aqua `#66E0F0`, Glacier `#8CCFFF`, Steel `#A9BDD4`, Periwinkle `#A3B4FF`, Lavender `#B9A8FF`, Orchid `#E2A9F3`, Platinum `#D5DBE0`. Every themed color is C with each RGB channel multiplied and rounded half up: background × 0.24, contour texture × 0.36, well rim × 0.48, AOD × 0.75 (Q13), and lit bezel ticks × (0.45 + 0.55 × (i + 1) / n) (Q10: 0.45 is the comet's base, the dim end it fades toward, not a color drawn by itself). Colors that stay the same in every theme: black (wells, text on the time band), white and gray (numbers, icons, lead tick), unlit tracks `#2E3330`, unlit bezel ticks (`#343B37`, `#4A524D` every 5th, `#69736D` at 12/3/6/9), warning colors (Q3) and zone colors (Q37). The active theme is set in the built-in default face config; changing it means editing that one line and sideloading again. An on-watch theme menu and sleep mode (C × 0.6) come later |
| Q43 | Contour texture (agreed 2026-11-14) | Topographic contour lines on the background, only visible in the gaps between wells, never in AOD. Built from the design's formula (closed wavy lines r = 13·l·f(t) around (132, 318), every 5th line bolder) but need not match it pixel for pixel: about 40 lines about 13 px apart, the same center, every 5th line bolder, exactly two colors (C × 0.36 on C × 0.24). Each line is cut in advance, at build time, into pieces that stay inside the background disc and outside every well (the battery well included, which has no rim), so the texture can be drawn into the static layer at any time without covering a well. If the first frame after a return from a widget, texture included, is still no slower than today's (Q44, which wins over any allowance; agreed 2026-11-14), the texture is drawn at once; otherwise it is drawn in batches paced by a short animation (about 0.5 s, spreading out from (132, 318)) while the screen is awake, and whatever is left is finished at once when the screen goes to sleep. Never one batch per 1 s update. Line thickness may vary slightly along a line. Plain lines are built first, then filled strips are tried, and the faster on the watch is kept; a pre-rendered gray image tinted per theme is the last fallback, only if the batch frames are still too heavy. Lines meet at mitred rather than round joins |
| Q44 | Drawing tiers and cost limits (agreed 2026-11-14) | The static layer also holds the unlit bezel ticks. For the per-second update two designs are prototyped and the cheaper one kept: a second full-screen buffer holding everything that changes at most once a minute (copied each second, then the heart-rate field and the seconds drawn over it), or system layers (`WatchUi.Layer`) redrawing only the small parts that change each second. Either way the face falls back to today's full repaint when the graphics pool has no room. Acceptance, measured the same way before and after in the simulator profiler and on the watch: the per-second high-power update at most 10% slower than today's; AOD does no extra work; the first frame after a return from a widget is not slower than today's |
| Q45 | Long-press targets of the bottom field and the bezel ring (agreed 2026-11-15, on-watch acceptance) | The bezel ring is no long-press target: its 14 px band at the screen's edge was too hard to hold on the watch. The bottom field's target is its pill padded 10 px left, right and below and 4 px above (the rounded rect 116, 332, 184, 54 with half-circle ends, still 4 px clear of the center field's target), so it includes the pill's rim; it was the unpadded pill, also hard to hit. Holding it opens the steps page, as before. The round fields keep their wells (R + 6). Q5 still holds (steps opens from the bottom field); changes Q39's note for the bottom field |
| Q46 | Publishing and license (agreed 2026-11-26) | The repository is public: `github.com/fugo101/wellface`. License Apache-2.0 (`LICENSE`), with a `NOTICE` that reads "Copyright 2026 FuGo" and lists third-party material. The bitmap fonts in `resources/fonts/` are generated from Big Shoulders and Manrope, both SIL OFL 1.1, and stay under it (the OFL texts sit next to them). The Garmin SDK, the device files and Garmin's fonts are never committed (the Connect IQ developer agreement does not allow redistributing them). The README says the project is developed with Claude Code, and that Garmin, Forerunner and Connect IQ are Garmin trademarks and Wellface is not affiliated with Garmin. Nothing personal goes into the repo: no names, emails, machine paths or personal health numbers |
| Q47 | Device support policy (agreed 2026-11-26) | A community project: the maintainer guarantees only the Forerunner 265 ("maintained"). Any other device is "community": its porter owns the watch, starts with an issue, and the port's PR carries simulator screenshots (Always On heat map included) and a confirmation from the real watch. The porter is listed in `.github/CODEOWNERS` for that device's files and is its maintainer. A community device that breaks across a release and is not fixed is removed from `manifest.xml`. A port must not change a single FR265 pixel (the FR265 golden tests stay unchanged). Until the multi-device refactor lands (first planned issue: "make adding a device purely additive", ending with an experimental, simulator-only 360×360 FR265S sample port), `CONTRIBUTING.md` asks for an issue before any port. The 360×360 FR265S stays unsupported until then |
| Q48 | CI split (agreed 2026-11-26) | Required checks need no Garmin account: `Conventional PR title` and `Lint` (shellcheck for `scripts/`, ruff for `tools/` Python, actionlint for the workflows). A Monkey C compile-only build for every device in `manifest.xml` runs on push to `main` and on same-repo pull requests; it is not required, because fork PRs get no secrets, and it skips cleanly when the secrets are absent. Simulator unit tests in CI are a later experiment (a GitHub issue); until then `scripts/run-tests.sh` on the contributor's machine is authoritative |
| Q49 | Garmin account and files in CI (agreed 2026-11-26) | The compile-only build uses the repository secrets `GARMIN_USERNAME` and `GARMIN_PASSWORD` of a dedicated Garmin account without 2FA. Each run downloads the SDK zip (version pinned, SHA-256 checked) and the device files fresh through a pinned `lindell/connect-iq-sdk-manager-cli`; nothing from Garmin is cached or republished, and no third-party Docker image is used. It signs with a throwaway key generated in the job, and runs in an `ubuntu:22.04` container. The real developer key never goes to CI. Facts and open questions: `docs/research/ci-and-distribution.md` |
| Q50 | Releases (agreed 2026-11-26) | GitHub Releases, SemVer, first release `v0.1.0`. One `wellface-<device>.prg` per device in `manifest.xml`, built on the maintainer's machine with the real developer key by `scripts/release.sh <semver>` (output in `bin/release/v<semver>/`, with SHA-256 sums); the script does not publish, the maintainer runs `gh release create`. The release notes carry the sideload and uninstall steps |
| Q51 | Language (agreed 2026-11-26) | Everything in the repo is English only: code, comments, docs, issues, commit messages. No translated copies of the docs. Two exceptions: data the watch itself returns, such as the Vietnamese weekday forms in Q21, and the Claude Design export in `design/claude-design/`, kept exactly as exported so a new export can replace it |
| Q52 | Issues, local files and history (agreed 2026-11-26) | Issues and specs live on GitHub Issues, not in files. `.scratch/` and `spikes/` stay on the maintainer's machine, untracked and gitignored, and are purged from the repository's history before it goes public; the data-spike scripts are deleted. What a ticket decided that must outlive it goes into `docs/` (this file, `docs/spec.md`, `docs/research/`) |
| Q53 | Design file and the Claude Design runtime (agreed 2026-11-26) | `design/claude-design/` stays in the repo, `support.js` included: it is the runtime that Claude Design generated, not the project's work and not covered by Apache-2.0 (`NOTICE` says so), and it is kept only so that `FR265 Watch Face.dc.html` opens. The final design is still the reference for pixel measurements |

## Final design: main elements
Coordinates are on the 416×416 canvas, center (208,208), as of the design update of 2026-11-14 (the update banner in the design file). Full details in `spec` inside the design file. Colors below are the mint theme; every themed color follows Q42.
- **Draw order:** background → contour texture → edge mask → bezel ticks → well rims → wells → content. Background, texture, edge mask, unlit bezel ticks, well rims, wells, the time band and the tracks form the static layer (Q44).
- **Background:** fillCircle r 194, accent × 0.24 (`#22362C`). Contour texture (Q43) in accent × 0.36 (`#335242`), pen 2, every 5th line pen 3. Edge mask: a black ring r 201, pen 14, over whatever spills past r 194.
- **Bezel ring:** 60 radial bezel ticks, tick i at 6i° clockwise from 12 o'clock, each a flat-ended line from its inner radius to r 208: ordinary ticks r 201, pen 3; every 5th tick r 198, pen 4; ticks at 12/3/6/9 o'clock (i = 0/15/30/45, that is 0/25/50/75% of the goal) r 196, pen 5. Unlit: `#343B37`, `#4A524D`, `#69736D`. Progress p = min(1, steps / goal); n = 0 when p = 0, else min(60, floor(p × 60) + 1), so tick i lights once p ≥ i/60. Ticks 0…n−2 lit in accent × (0.45 + 0.55 × (i + 1) / n), dim at 12 o'clock and brighter toward the front; tick n−1 is the lead tick: white, from r 195, pen max(4, its own pen). Goal reached: all 60 ticks in the accent, no lead tick. No steps, no goal or goal 0: all 60 unlit.
- **Well rims (Q39):** accent × 0.48 (`#446D58`), 2 px outside the well: time band fillRoundedRectangle(56, 70, 304, 104, 32); left field fillCircle(88, 252, 46); right field fillCircle(328, 252, 46); center field fillCircle(208, 262, 68); bottom field fillRoundedRectangle(124, 334, 168, 44, 22). A well is a 6 px black border around each element.
- **Battery:** unchanged. 10 arc segments r 180, stroke 4, segment i from −34 + 7i° to −29 + 7i° (flat ends). Well: arc stroke 12 from −36° to +36° with 2 round caps. Lit segments = ceil(battery/10). Off segments `#2E3330`.
- **Time band:** well (58, 72, 300, 100) radius 30; band (64, 78, 288, 88) radius 24, accent color.
- **Time:** Big Shoulders 86 px (Q8/Q16), tabular digits 42 px, `:` 21 px, `08:42` 189 px wide, centered on x 208, baseline y 155, in black; same place and size in AOD (filled, accent × 0.75, Q12, Q13).
- **Seconds (Q41):** Manrope ExtraBold 26, black, left-aligned at x 309, baseline y 155, high-power only.
- **Date:** pill at y 162, height 28, radius 14, width max(96, text + 2 × 14) up to 272, centered on x 208, overlapping the bottom edge of the time band. Manrope ExtraBold 17, letter spacing 2, text centered on y 176, format `THU 12/11` (Q38). The weekday in the accent, day/month in white, the whole text centered as one group. AOD: 3 px outline and the whole text in the AOD color.
- **Left field (stress):** center (88, 252) R 38, icon at (76, 222), number centered on y 266. Gauge centerline r 35, pen 6, round caps. Icon 24 px. Manrope number 26, size shrinks with character count (≤3 → 26, 4 → 22, ≥5 → 18).
- **Body Battery:** center (208, 262) R 60, icon at (196, 219), number centered on y 274. Gauge centerline r 54, pen 12, round caps, and a white dot r 3 at its end (only when the value is above 0). Lightning-bolt icon. Manrope number 48.
- **Heart rate:** center (328, 252) R 38, icon at (316, 222), number centered on y 266. 5 arc segments, centerline r 35, pen 6, segment i from i×72° + 9° to (i+1)×72° − 9°, round caps (about 8° of visible gap). Lit segments = number of HR-zone thresholds ≤ heart rate, each in its zone's color (Q37); unlit ones `#2E3330`. No data: `--` in gray.
- **Steps:** pill (126, 336, 164, 40) radius 20, 8 px below the center field's well. Contents centered on y 356 (`/ goal` on y 357): foot icon at (140, 344); number Manrope ExtraBold 22 right-aligned at x 228; `/ goal` Bold 15 left-aligned at x 233, centered on y 357. Fit rules as Q24, Q25, Q34; thousands separator is a dot (`1.147`). When the goal is reached: pill in the accent, foot and number black, centered as a group.
- **Color rule:** the accent is used as-is only for the time band, the weekday in the date pill and progress (gauges, lit battery segments, lit bezel ticks, which ramp from accent × 0.45 up to the accent, Q42). Zone segments use their zone colors. Icons are gray `#8C8C8C` and only change color on a warning, together with their ring.
- **Missing data:** stress, HR or Body Battery shows `--` in gray, track only.
- **Fonts to export:** the time font at 86 px, filled only (also used in AOD), glyphs `0–9 :`. Manrope ExtraBold 17 (date), 18 and 22 (steps; heart rate with 4–5 characters), 26 (stress, heart rate up to 3 characters, seconds), 48 (Body Battery); Manrope Bold 15 (`/ goal`). Each font holds only the glyphs it draws (Q32), from `0–9 A–Z / . -` and space. No `%` or `h` until a Q15 metric is built.
